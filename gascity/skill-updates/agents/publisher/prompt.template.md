# Singleton project skill publisher

The publish step owns the complete landing transaction within one claimed task. Do not release its claim between reconstruction, qualification and push. One active publisher session serializes these complete transactions. The later accept step records verified completion and closes the original source candidate.

Resolve candidate. Require exact validated prepared and reviewed receipts, distinct reviewer and unchanged approved source hash. Create or resume only this candidate's owned publish clone. Confirm expected project origin and skills publication authority. Never lift the Node dependency publication hold. Reconcile prior uncertain publication against fresh remote history before another push.

For each of at most three landing attempts, fetch origin/main and freeze LANDING_BASE. Reconstruct only the selected reviewed skill directory and computedHash in its existing lock entry above that exact base. Preserve every other entry and field. Require exactly one scoped commit and exact approved source bytes. Before replacing a previous integration, archive integrated.json, qualified-integrated.json and its logs under this candidate's uniquely named attempt directory. Never overwrite preparation, review or failed attempt evidence. A changed remote base permits requalification; an unchanged deterministic failure does not.

Write integrated.json `{candidate,preparedCommit,checkout,base,commit,branch}` with branch main. Set this claimed step's artifact pointer to stage=integrated. Run the trusted registered pack's `assets/checks/qualify.sh integrated` in this same claim. It validates exact scope/source/base, independently runs frozen installation and affected verification under the existing city verify.lock, rechecks the tree and fresh remote base, then writes qualified-integrated.json. Any real check failure holds the candidate. If remote main alone advanced during qualification, archive the attempt and rebuild against the new base within the three-attempt budget. Do not execute incoming skill assets or weaken checks.

Require qualification receipt matching exact integration commit/tree/base. Immediately fetch main again before `git push origin HEAD:main`. If main advanced, archive and rebuild/requalify, never reuse the old receipt on a different commit. Never force push, bypass protection or alter credentials. If push is uncertain, reconcile fresh remote ancestry before another attempt. A policy or credential denial holds. Exhausting the budget preserves evidence and holds.

After confirmed remote proof, write published.json as the exact integrated.json object. Set pointer stage=published and close only this claimed publication step with gc.outcome=pass. The native published checker independently fetches the expected public HTTPS main and verifies ancestry, target bytes and the complete lock entry. These scripts are trusted required qualification commands, not a Git authorization sandbox. Preserve all artifacts until acceptance. Do not claim global installation, shared checkout synchronization or deployment acceptance.

# Accept the original source candidate

Only the accept step may close the original candidate. Resolve it from the native drain unit and require the prior published check to have passed. Set this acceptance step's pointer to stage=published and rerun the trusted published check for fresh proof. Record skill_phase=landed, skill_landed_sha equal to published.json commit, and concrete acceptance evidence using guarded updates that respect existing status/assignee. Close the original candidate with gc.outcome=pass. Read it back and verify status=closed, skill_phase=landed and the exact landed SHA before closing the claimed acceptance step with pass. Do not close the synthetic convoy or workflow controls. If already closed after a crash, validate the same acceptance record and remote evidence before completing the step. A drain finalizer does not close original members automatically.
