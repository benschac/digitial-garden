A scan has no item input convoy or original candidate; do not apply item candidate lookup or write a fabricated `{candidate,stage}` item receipt. Derive `SCAN_DIR="$GC_CITY/.gc/skill-updates/$CLAIMED_STEP"` and use its `scan` child for the owned clone. Require the durable directory to remain physically under the actual city, outside molecule storage and outside the removable clone; reject symlink escapes or contradictory existing identity. The scan root and claimed step are native identities, never guessed candidate IDs.

Claim the scan step as described above. In a fresh owned scan clone under `$GC_CITY/.gc/skill-updates/<scan-step>/scan`, fetch expected origin/main and record its full commit. Inventory every existing lock entry and tracked skill directory. Untracked/custom directories and unsupported/non-GitHub sources are outside automatic updates. Source shorthand must be owner/repo, and skillPath a safe relative path ending SKILL.md. Before creating or dispatching any candidate, require successful trusted registered `node scripts/skill-update.mjs scan-admission CHECKOUT SKILL` for its selected entry in that scan checkout. This checks the installed hash against computedHash and unconditionally holds any entry with a customization field, including malformed markers and matching installed hashes. Any admission failure requires a persistent review hold and exclusion from the automatic convoy; never substitute the hash command or remove a marker to pass admission. The hash command remains a content hash only. Also inventory the registered checkout read-only and record any divergence from remote main. Never claim the working tree is synchronized by a remote publication or overwrite locally missing/customized skills. Do not mistake missing lock entries for install requests.

Fetch each public GitHub source without executing hooks or assets, pin its full 40-character commit, locate exactly the existing skillPath, and compute the target directory hash. Compare actual bytes, not only dates or repository HEAD. No change means no candidate. Keep source revision/hash/path provenance. New or removed names, unsupported modes and uncertain changes become persistent held candidates for review. Never resolve a rename by guessing.

Before creating or dispatching a candidate, list ALL states with `gc --city "$GC_CITY" --rig personal-site bd list --all --limit 0 --label skill-update --json`. Existing holds are not daily retry authorizations. Preserve prior attempts. A failure to read the full queue fails the scan instead of becoming an empty queue.

For each new eligible target, create a persistent task labeled skill-update with metadata skill_name, skill_source, skill_path, skill_current_hash, skill_target_hash, skill_target_revision, skill_scan_base and skill_phase=prepare. Verify that convoy and candidates share the rig store. Inspect convoy membership and existing workflow roots before dispatch so a crash after sling cannot launch the same batch twice. On partial failure reuse original candidates and the valid convoy; never duplicate them. More than 100 candidates requires separately recorded batches.
