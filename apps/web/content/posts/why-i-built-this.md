This site is meant to be more than a portfolio snapshot. It is a place where a project can retain the experiments, decisions, and technical notes that made it possible.

## A public surface with private depth

The public side should stay quick to read and easy to navigate. Behind it, the workbench can grow into a private studio for drafts, tools, and longer-running workflows.

That split matters. Published writing belongs in version-controlled files that are reviewable and portable. Mutable behavior—reactions, comments, analytics, or a future drafting workflow—can earn database state when it has a real use case.

## Start with durable primitives

The initial system is deliberately small:

- Markdown for prose-first writing
- MDX only when an interactive component improves the explanation
- validated metadata for reliable indexes and feeds
- static pages that remain readable without client-side JavaScript

The goal is not to predict every future feature. It is to make the next useful addition straightforward without weakening the source of truth.
